# Runbook — multi-region (заготовка)

> Пошаговые инструкции для операций, которые появятся в Спринте 8.

## Как добавить новый регион

1. Поднять инфру (Postgres, NATS, Redis) в новом регионе.
2. Задеплоить сервисы (тот же docker-compose, региональные env).
3. Настроить подписку на глобальные таблицы (`tenants`, `tenant_settings`).
4. Подключить NATS-мост к route-стриму.
5. Проверить healthcheck и smoke-тест (создать тестовый tenant в регионе).

## Как переключить tenant на другой регион

1. Проверить, что целевой регион здоров.
2. Остановить флоу tenant'а (orchestrator: `cancel` всех flows).
3. Скопировать бизнес-данные tenant'а в целевой регион.
4. Переключить `tenants.home_region`.
5. Возобновить работу (новые события пойдут в целевой регион).
6. Инициировать удаление старых данных (после N дней).

## Как делать failover

1. Детект: healthcheck глобального слоя / алерт.
2. Переключить route: `home_region` затронутых tenant'ов → резервный регион
   (если данные реплицированы) или включить read-only режим.
3. Уведомить операторов (`analytics.alert` / внешний алертинг).
4. После восстановления — синхронизировать расхождения.

## Откат (rollback)

1. Вернуть `home_region` на прежнее значение.
2. Проверить, что очередь NATS не потеряла сообщения (durable consumers).
3. Сверить метрики.
